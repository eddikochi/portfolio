# Portfolio Eddi Kochi — Plano de Evolução V1 → V4

## 1. Objetivo

Evoluir o portfólio atual para uma experiência editorial, autoral e orientada a evidência, sem perder a profundidade dos cases profissionais existentes.

A V4 não é um redesign puramente visual. Ela reorganiza o posicionamento profissional para demonstrar como UX, CRM, CRO, Product, dados e governança operam como partes de um mesmo sistema.

---

## 2. Princípio da migração

**V1 = fonte de verdade e profundidade.**  
**V3/V4 = arquitetura, hierarquia, narrativa e linguagem visual.**

Não apagar o conteúdo profissional existente. Migrar, editar e reorganizar o que comprova experiência real.

Nunca:
- inventar métricas;
- apresentar discovery como produto lançado;
- apresentar proposta como resultado;
- criar clientes, cargos ou resultados inexistentes;
- inventar e-mail, domínio ou links;
- usar `®`;
- transformar a Home em página comercial de freelancer.

## 14. UX e navegação

### Produção

Não implementar cases como modal/overlay.

Usar páginas/rotas reais.

Home:

`/portfolio/`

Cases:

`/portfolio/work/pdp/` etc.

Cada case deve ter:
- header próprio;
- link “Back to work”;
- URL copiável;
- title/meta description próprios;
- navegação para próximo case.

### Mobile

Validar:
- headline do hero;
- ausência de overflow horizontal;
- chips;
- cards;
- grids;
- tamanho mínimo de toque;
- leitura dos cases;
- sticky navigation.

## 15. Visual system

Direção:

- editorial / Swiss;
- off-white + near-black;
- accent orange;
- tipografia grotesk;
- grid forte;
- radius mínimo;
- sombras praticamente inexistentes;
- muito espaço negativo;
- imagens grandes;
- linhas e bordas como estrutura;
- microinterações discretas.

Evitar:
- gradients;
- glow;
- cards SaaS arredondados;
- excesso de badges;
- estética genérica de template de IA.

## 18. Critérios de aceite V4

A V4 está pronta para substituir a atual quando:

- os três cases profissionais estiverem migrados;
- PDP estiver validada como template;
- todos os links reais estiverem conectados;
- Resume estiver correto;
- nenhuma métrica não comprovada aparecer;
- trabalhos conceituais estiverem claramente rotulados;
- mobile estiver validado;
- não houver scroll aninhado/modal nos cases;
- cada case possuir URL própria;
- conteúdo visual real tiver substituído placeholders principais;
- Lighthouse/acessibilidade não apresentarem problemas críticos;
- a Home funcionar tanto para recrutador quanto para potencial projeto independente sem parecer uma landing page de serviços.
